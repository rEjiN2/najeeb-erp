# Ala Dates ERP: Frontend

Next.js (App Router) + TypeScript strict, pnpm, Tailwind + shadcn/ui,
recharts. UAE dates-trading ERP replacing a legacy system (atACC).
Backend: the NestJS API at API_BASE_URL (server-only env var).

## Working rules (read first)

- Be economical. Read only the files you need; do not scan the whole repo.
  Check "Where things live" before searching.
- Before building anything, look for a shared component or pattern that
  already does it. Extend it with a prop rather than copying or rewriting.
- Do not guess field names or response shapes. Read the backend DTOs and
  controllers in the sibling folder `Ala-Dates-Backend` (read-only
  reference, never edit it from here) or ask me.
- Keep command output small: run typecheck and lint quietly, and do not
  paste long logs back into the conversation.
- Do not add libraries without asking. Do not commit unless asked.
- Finish every task with a summary of at most 10 lines: what changed, what
  you checked, anything I must decide.

## Where things live (verify on first use, then correct this section)

src/features/<domain>/ (api.ts typed server functions, components, types),
src/components/ (shared UI), src/lib/ (server-only API client, helpers),
AuthContext abstraction, (protected) route group with the app shell,
design tokens in one file, shared Master pattern, shared Voucher pattern,
shared Activity panel, DemoDataBadge.

## Conventions

- Data: fetch on the server through one typed function per feature
  (features/<x>/api.ts), forwarding the user's cookie. Use cache: "no-store"
  for lookups and live data. Every screen handles 401 (go to login), 403
  ("no permission"), loading skeleton, empty and error states. Never fall
  back to mock data; any mock widget carries the "Demo data" badge.
- Auth: the backend sets httpOnly cookies. Never read, store or forward a
  token in client JS.
- Master pattern: list with search, filters and pagination, plus a side
  panel form. Codes are generated by the backend and shown read-only.
  Show backend validation messages on the form. When delete is blocked,
  offer "Deactivate instead".
- Voucher pattern: list page (filters, sort and page kept in the URL query),
  then /new, /[id] (read-only view) and /[id]/edit. No Delete: use Cancel
  with a required reason. View page shows the created/updated/cancelled
  meta strip and the Activity panel (audit plus comments). Print and
  download PDFs through a Next.js route handler that streams the backend
  response.
- Dropdowns come from backend /lookup endpoints (accounts with
  scope=company or scope=party, parties, cashiers, locations). Never hardcode
  business rules such as allowed parent types; fetch them.
- Formatting: amounts as AED with 2 decimals; times shown in Asia/Dubai.
- Design: tokens live in one place. Inputs are 5px radius, about 36px high.
  Charcoal base with an amber accent; no default shadcn blue; keep dark-mode
  variants. Do not restyle individual components.

## Business context

Dates trading company: customers and suppliers, cash/bank/wallet accounts,

groups (Dates, Packaging, Gift & Bundle) and bundling as a core feature.
